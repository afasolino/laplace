# G10 — Idle/Sleep Consolidation and Controlled Self-Improvement

Implement maintenance first in SHADOW mode. The phase may be certified while the feature lifecycle remains `SHADOW`.

## Execute

1. Inspect current Hermes maintenance/memory-learning mechanisms and AutoDesign meta-harness optimization; record exact commits/licenses.
2. During bounded idle windows analyze trajectories/memory to propose episodic summaries, durable facts, contradiction/supersession updates, obsolete-memory demotion, candidate skills, recurring failures, candidate process/harness improvements and optional candidate code changes.
3. Shadow mode must not silently modify production code, activate skills, delete durable memory, alter authoritative rules or change routing/security policy.
4. For meta-harness improvement use an AutoDesign-style loop:
   - identify one bounded change;
   - create candidate;
   - A/B current versus candidate on frozen tasks;
   - include held-out/development tasks;
   - reject any correctness/security regression;
   - produce evidence;
   - require explicit human approval before promotion.
5. Never permit unrestricted recursive self-modification.
6. Bound GPU time, tokens, disk growth and maintenance frequency.

## Gate

Run multiple controlled idle cycles including contradictions, duplicate proposals, crashes and restart.

Require complete provenance, no unintended production mutation, crash-safe/idempotent maintenance, bounded resources, deterministic A/B evidence and no auto-promotion.

Certify the mechanism; keep self-improvement SHADOW until human-approved.
